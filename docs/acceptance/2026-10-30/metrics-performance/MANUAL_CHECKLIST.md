# RC 06 人工／設備補驗清單

本票自動量測使用獨立副本、一般使用者及隔離 LOCALAPPDATA，不重啟 Explorer、不關閉或替換原持續桌布。下列項目目前 **NOT RUN**，依 2026-10-30 spec 決策交接 08／09，不以受控訊息或手動暫停代替真正 OS 事件。

| 項目 | 原因 | 操作與判準 |
| --- | --- | --- |
| 真正鎖定／解鎖 | 會中斷互動工作階段，需人工操作與確認 | 同機同電源／亮度，兩主題各一／雙目標；先 Active >=600 秒，再 Win+L，Locked >=600 秒，解鎖確認新握手／推送／JS 回應。往返五次，記 OS 事件時間、恢復延遲及逐程序 CPU／GPU／資源。比較 CPU 是否下降；未下降須調查 |
| 真正關屏／恢復 | 不能為讀畫面或查值自行喚醒螢幕 | 人工關屏並記時間，保持關屏 >=600 秒；由既有觀測檔確認沒有電源保持要求，恢復後再讀檔。五次往返，記實際 display notification／paused／恢復；手動暫停結果不能代替 |
| 待機／喚醒 | 需真實 OS 及硬體事件 | 人工睡眠／喚醒，跨 CPU／網路基準重設、UI 可回應、採樣無補跑、各宿主恢復；保留事件時間與失敗日誌 |
| 全螢幕／部分覆蓋 | 需人工啟動及確認實際前景覆蓋 | 啟用智慧休眠，在單目標及雙目標用真正全螢幕程式覆蓋全部／部分顯示器，至少600秒；記有效政策、低頻／暫停、CPU／GPU 與恢復，不以模擬通知冒充 |
| NVIDIA／NVML 實讀與故障 | 本機僅 Intel Graphics，無 NVIDIA 設備 | NVIDIA 機器記 driver／NVML 版本、裝置識別及產品 EXE hash；與同期 nvidia-smi／NVML reference 比較同裝置、窗口與負載。分列缺 DLL、API failure、權限拒絕及裝置消失；失敗是 unavailable／error，不能顯示有效 0，UI 仍回應。不要為測試替換系統 DLL 或任意停用正在使用的裝置 |
| 實體網路受控高流量、拔線／換介面 | 無已確認可控實體 peer，不向第三方製造流量 | 對明確授權 LAN peer 做 RX／TX 各30個同期1秒窗口，記 bytes/s、介面 LUID、獨立介面計數器與負載；閒置、滿載、拔線／換網卡／恢復，warm-up／reset 不產生假0。允許差 <=max(64KiB/s,10%)，窗口兩端skew <=100ms |
| collector 每次 API 呼叫頻率 | 產品未公開逐次 collector 計數；原生推送時間戳非呼叫數 | 以另行確認的 ETW／原生診斷方式記 collector 起訖、調度間隔與執行成本；不得由 MetricsTick 推論。Active 設定1000ms，手動暫停0；保留本票 public worker 契約測試結果 |
| 其他 Windows／Runtime／硬體／解析度／DPI | 本票只有目前 Windows 11、Intel、雙1920×1080/DPI144／96 | 每組完整保存版本／hash與環境，重跑相同矩陣，不外推目前結果；單／雙宿主皆確認實際主題與附掛 |
| 更長 soak、100次熱切換資源與因果增量 | 本票預定1800秒固定主題與600秒情境；舊切換觀測不套新hash | 08／09另定100次A↔B的穩定等待、暖機與前後閒置窗口，保留完整程序生命週期與長時trend；新增健康探針要判斷獨立增量時用同條件舊／新版本對照，不能只減去舊歷史數值 |

防毒每次攔截均記 Trend Micro Apex One 的產品、規則名稱、精確時間、EXE／父程序、受影響項目及證據；受影響項記 **BLOCKED**，不得當產品 FAIL 或修改防毒設定。解壓／執行位置必須是非 Temp 使用者繁中／空白路徑，由 Node 直接啟動 EXE。完成後只對已核實 path／建立時間／handle 的測試程序使用正式退出；原持續桌布保持不動。
